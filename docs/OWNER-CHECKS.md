# Owner-only qualification (not performed during implementation)

Do this with disposable synthetic text, after reading the disclosure and explicitly pressing Start on-device. Never test with a real password. This checklist is deliberately separate from automated simulations.

1. Launch the bundle. Verify the native right-hand system icon shows pause/OFF; reopen menu, confirm no recording files created. Quit/relaunch remains OFF.
2. Press Start, read disclosure, cancel. No capture. Start again: deny Input Monitoring and Accessibility and verify actionable failures with no event files containing keys. Grant only via System Settings as described in README; reopen if requested.
3. Timing-only: in a disposable TextEdit plain document, type `SYNTHETIC abc`, hold/release a key, repeat, Shift, overlap two keys, Backspace, click/hold and scroll. Pause. Inspect JSONL for key codes/timing but no `text` or `title`. Modifier holds are not inferred. App event-target annotation may be unavailable on a particular OS: that context remains unsupported; do not relax gates.
4. Opt in to text, Start again. Type synthetic text in TextEdit and Xcode editor. Confirm event characters exist only for those verified text areas. Test an IME/dead key; expect incomplete/suppressed text, not a final document. Never expect paste/voice/autocorrect to appear as final text.
5. Add `com.apple.TextEdit` to exclusions. Start and verify no input records from it. Test unsupported browser/terminal/password-manager windows using synthetic text only. Pause must stop immediately, including held keys; pressing Start later must not match releases across the boundary.
6. With only a synthetic editor document open: lock, unlock, sleep/wake, switch user/session and switch editor fields. Verify no keys/mouse during the protected intervals and boundary/reset records on return. If any protected events appear, Pause, delete this test recording and report the OS/app combination; do not collect personal data. Lock-state signals are not universally contractual. Revoking Accessibility/Input Monitoring during a synthetic session must stop data promptly (per event and ≤1s polling) and require Start again.
7. Set 0.01 hours for a short synthetic deadline test, including a sleep/pause period. Verify auto-pause and separate active/excluded/sleep/paused time. Restore 84 hours. Changing the window pauses and restarts only via explicit Start; process restarts begin a new OFF run.
8. Export both types locally outside Git/cloud folders. Redacted output must omit text, title, app identity, coordinates, key codes and modifiers. Run offline summary. Delete all via app; exports/backups require separate deletion. Never send personal JSONL/logs with a bug report.
9. Inspect session callbackCount/TotalNS/MaxNS and Activity Monitor during representative synthetic typing and optional motion. Core benchmarks exclude the AX/TCC/WindowServer path; turn motion off if overhead or tap disables occur. Any tap disable pauses and reports possible loss; known drops are a lower bound.
10. Only after qualification, choose 84 hours, optional text capture and exclusions, then Start the personal session. Sleep/lock may resume an already enabled session with WAIT/REC visible; Pause persists only in this process, and launch-at-login always starts OFF. Keep the app running and inspect cap/remaining time. Export before 14-day retention removes old files.
